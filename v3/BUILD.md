# Build

Current package: **Beta 8**, `3.0.0~beta.8`; see [BETA-8.md](BETA-8.md). All native components and the companion now target iOS 15.4.1. Exact 19E258 profiles are added alongside the existing 20A357 and 20G75 paths. No physical-device acceptance has been performed for beta 8. Native lease lifetimes are now 30 seconds (media adapters) and 60 seconds (session helper), refreshed every second; text below that says eight seconds describes earlier packages.

Previous package: **HTTPS3 compatibility beta 1**, `3.0.0~beta.5+https.3.open.2`. It adds exact implementation profiles for the four frameworks reported by the iOS 16.0/20A357 arm64e tester. `HostProfile.mm` is linked into the standalone helper; the three media profiles are in the universal injected adapter. The original 16.6 paths below remain alongside these new experimental paths. Historical candidate labels below describe earlier revisions.

Build on the prepared Mac with Xcode/iPhoneOS SDK, Python3, Node20+ (tests), FFmpeg (validation), and Homebrew OpenSSL3 headers. Run `python3 v3/build.py` from the diagnostics repository. It builds/signs arm64 executables, the UIKit companion, native service launcher, crypto bridge, AudioToolbox AAC decoder and network-address bridge, plus a universal arm64/arm64e media-service adapter, then constructs a root-owned rootless DEB under `dist/v3`.

The link input at `build/v3/device/libcrypto.3.dylib` must be the unmodified arm64 library from [Procursus libssl3 3.2.1, rootless 1800/iOS 15](https://apt.procurs.us/pool/main/iphoneos-arm64-rootless/1800/openssl/libssl3_3.2.1_iphoneos-arm64.deb). Package SHA256: `cea1b21c8f11c7bb7ca963dd115e837e8041298056695a32ca5ddb4190e17d75`. Extract `var/jb/usr/lib/libcrypto.3.dylib` from its data archive; library SHA256: `3aaee548e5b231766642d762f5c31217518633ac3161afc7cf9f27e4cb098f5f`. The builder rejects other inputs. This library declares minOS 15.0; the old iOS 16 link input must not be substituted or have its load commands patched. The signed Procursus Release/Packages metadata and hashes were verified during this port, and all 41 bridge imports resolve. All 7,988 library exports match the previous link input.

OpenSSL is an external dependency, not bundled in the DEB or source archive. Its install ID is `@rpath/libcrypto.3.dylib`; standard-rootless runtime resolution must reach `/var/jb/usr/lib/libcrypto.3.dylib`. The verified package also requires `libiosexec1 (>= 1.3.1)` and `ca-certificates`; use the device's matching repository and let its package manager resolve dependencies. The inspected iOS 15 libiosexec1 also declares minOS 15.0. Current Homebrew OpenSSL 3.6.3 headers were checked against the official 3.2.1 headers for the public structures/constants used by this bridge, and the final link verifies the required symbols. These static checks do not replace an on-device crypto/session test.

The `src/Common.m`, `src/NativeIdentity.mm`, `src/HostPayload.mm` and associated headers are required alongside `v3/`. A matching source archive accompanies the beta. The package builder neither connects to nor installs on a phone. `v3/tests/` contains host tests; set `CDV3_CRYPTO` to the host-built OpenSSL bridge when running them. The separate Mac `receiver/` remains a research/reference implementation, with its duplicate-launch fix and its own manual launcher.

The release source archive includes `SOURCE-COMMIT.txt`, expanded by Git during export, so building the archive does not require a `.git` directory. It includes V3, shared native sources, and reference libraries/tests; the Mac-specific research launcher remains available in the repository.

Build the host crypto bridge before running Python tests:

```sh
mkdir -p build/v3/host
xcrun clang -dynamiclib -Wall -Wextra -Werror -I"$(brew --prefix openssl@3)/include" v3/native/Crypto.c -L"$(brew --prefix openssl@3)/lib" -lcrypto -o build/v3/host/libcardashcrypto.dylib
codesign --force --sign - build/v3/host/libcardashcrypto.dylib
xcrun clang -dynamiclib -Wall -Wextra -Werror v3/native/AudioDecode.c -framework AudioToolbox -o build/v3/host/libcardashaudio.dylib
codesign --force --sign - build/v3/host/libcardashaudio.dylib
xcrun clang -dynamiclib -std=c11 -Wall -Wextra -Werror v3/native/VideoDecode.c -framework VideoToolbox -framework CoreMedia -framework CoreVideo -framework CoreGraphics -framework ImageIO -framework CoreFoundation -o build/v3/host/libcardashvideo.dylib
codesign --force --sign - build/v3/host/libcardashvideo.dylib
CDV3_CRYPTO="$PWD/build/v3/host/libcardashcrypto.dylib" CDV3_AUDIO="$PWD/build/v3/host/libcardashaudio.dylib" CDV3_VIDEO="$PWD/build/v3/host/libcardashvideo.dylib" python3 -m unittest discover -s v3/tests
node --test v3/tests/test_*.mjs
node --test receiver/test/*.test.mjs
python3 receiver/test/session_lock_test.py
```

The loopback adapter is compiled from `v3/native/Loopback.mm` and injected only into `mediaserverd` through the installed Substrate-compatible provider. Its exact APTransport profiles cover the inspected 20G75, 20A357 and 19E258 implementations; both hook locations also require matching instruction prologues. The profile table and firmware evidence are described in NATIVE-PROFILES.md. Do not relax these guards to enable another firmware without analyzing and testing that firmware. Readiness is published through Darwin notification state because the media service is sandboxed. The backend rejects startup if the matching adapter is unavailable. Device cache extracts and Apple framework binaries used for analysis are private research inputs and are not build or distribution payloads.

The service launchd job invokes `cardash-v3-service`, which records the exec boundary and executes the packaged Python backend. Fixed stderr phase labels identify Python entry, import completion and later startup boundaries without logging credentials. `DISABLE_TWEAKS=1` applies only to the V3 daemon and its helper children; it does not disable injection in SpringBoard, CarPlay apps or the media service. The job uses `ProcessType=Interactive`: the Adaptive configuration stalled before its entry point during a fresh userspace boot, while Interactive passed the recorded reboot trial with CarDash V3 closed. Warm restarts had passed under both modes and were not treated as boot proof. This result is specific to the tested device/bootstrap; see `TEST-RESULTS.md`. The installer/removal scripts restart the media service to load/unload this package's adapter. Installation does not start a CarPlay session.

Build the DEB first for the package audit. The browser test requires `npm ci --prefix receiver` and a deliberately started, supported physical-phone service forwarded to localhost:8890. It is not a simulator test. A forwarded USB browser test alone cannot validate the USB-free fix: separately disconnect USB and exercise a fresh session from a browser on the phone’s Wi-Fi/hotspot network. `CDV3_FULL_TRIAL=1 node v3/tests/browser-check.mjs <existing-evidence-directory>` keeps its owned headless browser open for the six-minute endurance trial and explicitly stops it afterward.

The service verifies its own 128 MB active/inactive budget through the XNU memorystatus API. On the tested Dopamine bootstrap, launchd's declared JetsamProperties were ignored; the kernel readback is the acceptance check. No other process's memory policy is changed. API definitions: [Apple XNU 8796 kern_memorystatus.h](https://github.com/apple-oss-distributions/xnu/blob/xnu-8796.121.2/bsd/sys/kern_memorystatus.h).

The optional-audio route adapter (`AudioRoute.mm`, `AudioVM.h`) requires a known MediaExperience profile, exact setter instructions and readable/executable or writable leaf VM mappings. It changes transient media-service state only during an owned CarDash host and a live PID-bound audio lease. The backend refreshes the lease every second; the monitor expires it after 30 seconds and preserves the latest observed native routing intent. It does not alter firmware on disk or Tesla driving restrictions. Do not relax identity guards for another firmware.

Beta 5's display geometry is negotiated per native session from the browser viewport. The geometry budget is at most 1,280 pixels wide, 960 pixels high and 921,600 total pixels; dimensions are even and the source remains at least as wide as tall. Native display declarations, HID bounds and MP4 dimensions must agree with the actual H.264 SPS. Browser presentation preserves aspect ratio, and iOS chooses the app grid. A fixed four-column layout is not a build guarantee. Initial Start and explicit Resize display negotiate geometry. Ordinary viewport changes only scale the existing native image; preserve generation checks and the selected audio output for manual resize.

HTTPS2 adds an experimental hosted frontend at `https://cfluid101.github.io/cardash-beta/option1/?v=https2`. Static assets use relative paths. The approved HTTPS origin obtains a memory-only browser token from the local phone; all media and control requests go directly to that local endpoint. Browser Local Network Access permission and secure WebCodecs support are required. The hosted path parses the existing bounded H.264/fMP4 stream and paints VideoDecoder output to WebGL/canvas; it does not silently select JPEG or MediaSource. The existing local HTTP page retains its capability-based fallback behavior, but the native-JPEG experiment failed on the supported iPhone with callback status `-12780` and is not a validated fallback. No Tesla firmware, gear state or vehicle setting is changed.

Keep overlay controls outside native geometry measurement: their visibility must not restart CarPlay. Only initial Start or explicit Resize display applies new geometry. A window resize only updates presentation and the sidebar arrow position; it sends no native command. HTTPS2 network and timeline recovery replaces the browser video stream only; it must not stop the native session or audio. Preserve the three-recoveries-per-minute bound, ten-second timeline-catchup cooldown, stale-callback checks and generation-bound touch release ordering.

The retained MediaSource path tracks random-access points from emitted MP4 fragments. It must not remove a range in the current GOP: MSE may extend removal through the next random-access point. Keep the one-tick safety margin and stale-session ownership checks. iOS’s wire-level `forceKeyFrame` restarts its screen bitstream, so continuous heartbeat-driven encoder resets are prohibited; only joining viewers and bounded long-GOP recovery request them. Canvas joins and recovery must remain bounded for the same reason.

HTTPS3 also compiles `v3/native/VideoBudget.mm` into the media-service adapter. It requires a known AirPlaySender profile, matching function bytes and executable mapping. The network-info override checks CarDash's display UUID and wired-CarPlay flags, then reduces only its advertised bandwidth while a valid PID-bound 30-second lease exists. Other displays receive the original dictionary. No Apple preference or framework file is modified. Startup checks this adapter before launching.
