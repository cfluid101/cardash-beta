# CarDash V3 Beta 5 — HTTPS3

A separate, phone-resident **native CarPlay video, touch and audio-output beta** for an iPhone 8 Plus on iOS 16.6 build 20G75 with a rootless jailbreak. Sessions have no fixed time limit. The receiver runs entirely on the phone; a running session needs no Mac, USB cable, SSH connection or browser setup code.

This receives the phone's real iOS 16.6 CarPlay interface. It does not install iOS 27 or emulate a newer CarPlay runtime. Original CarDash and V2 preferences remain separate.

**HTTPS3 supersedes the HTTPS2 tester build.** Use the matching `3.0.0~beta.5+https.3` package and [HTTPS3 tester page](https://cfluid101.github.io/cardash-beta/option1/?v=https3). The HTTPS site supplies static browser files; video, input, status and optional audio travel directly between the browser and the iPhone on the local network. They are not relayed through GitHub or another cloud service. Loading the hosted page initially requires internet access; this prototype has no offline cache.

HTTPS3 addresses progressive congestion with a scoped native encoder budget that starts at 3 Mbps and decreases when the browser reports delay. It preserves display geometry and audio while adapting. Canvas viewers no longer trigger periodic encoder restarts, a stalled viewer cannot hold native ingress indefinitely, and display recovery resumes after its cooldown instead of waiting permanently for Reconnect. Device-output ownership is isolated from unrelated native connection updates. See `TEST-RESULTS.md` for controlled tests and remaining Tesla validation.

## Install and connect

1. Install the DEB through Sileo or another dependency-aware package manager. Required bootstrap packages are `python3`, `libssl3`, `uikittools` and a compatible `mobilesubstrate` provider such as ElleKit. Installation briefly restarts the media service to load the USB-free adapter. The installer rejects unverified phone models/builds; do not bypass that check.
2. Open **CarDash V3** on the unlocked phone. Tap **Prepare CarPlay** once. This downloads approximately 18 MB from the pinned [DiPlay 0.2.22 release](https://github.com/shihabal3amri/DiPlay/releases/tag/v0.2.22), verifies the APK checksum and accessory identity, and removes the download after import. If downloading fails, save the same APK in Files and use **Import downloaded DiPlay APK**. No private identity is bundled with the beta. Preparation persists across sessions and package upgrades. The background service started automatically after the tested userspace reboot with CarDash V3 closed; the first unlock after a reboot is still required. **Setup complete** means no further preparation is needed; start the session from the browser.
3. Enable Personal Hotspot and connect the Tesla to it. Open the [HTTPS3 tester page](https://cfluid101.github.io/cardash-beta/option1/?v=https3), enter **http://100.99.10.2:8890/** as the iPhone address when the phone app reports that address ready, then tap **Connect**. Allow Local Network Access if the browser asks. Keep the colon before `8890`. The phone app lists other local addresses for ordinary Wi-Fi browsers. The existing local page at **http://100.99.10.2:8890/** remains available, but it does not supply the secure browser context needed for the hosted H.264 canvas renderer. V3 creates and verifies its own loopback address; it does not replace the original CarDash address.
4. Leave **Audio: Device output** selected to keep music on the phone’s normal output. Connect the iPhone to the Tesla by Bluetooth and select that audio source in the car. Tap **Start** in the browser. For streamed sound instead, choose **Browser audio**; changing the selection restarts CarPlay and the choice is remembered. Tap **Enable sound** if needed. **Mute/Unmute** and **Retry sound** apply only to Browser audio.
5. Use the native icons and Home button. The controls hide after the first displayed frame; **Controls** restores the scrollable panel and **Hide controls** dismisses it. These actions do not resize or restart CarPlay or change audio. **Stop** ends the session. Historical locked switching results for Waze/YouTube Music are recorded separately in `TEST-RESULTS.md`; they are not HTTPS3 acceptance results.

The session continues while browser heartbeats arrive. Closing/disconnecting the browser ends it after about 12 seconds; a session started from the phone waits up to 45 seconds for its first viewer. If iOS supplies no native video within 45 seconds, startup stops with an error. This startup deadline and the disconnect checks do not limit a streaming session. Native protocol sockets listen only on loopback.

Beta 5 requests a native display shaped to the full browser viewport and preserves its proportions. Source dimensions are capped at 1,280 pixels wide, 960 pixels high and 921,600 total pixels; narrow previews keep the source at least as wide as tall. **iOS selects the app grid**; four columns and three rows are not guaranteed. CarDash cannot occupy Tesla's surrounding system controls.

The browser that starts a session owns automatic sizing. A genuine window-size change, after a 1.2-second quiet period, restarts that native session to apply new geometry and retains the audio choice; this can briefly interrupt video and audio. Overlay visibility and status-label wrapping do not cause a resize. A second viewer or reloaded page observes the existing geometry. Select **Fit display** explicitly to adopt that viewer's dimensions. Avoid controlling the same session from several windows during a test.

On the hosted page, a transient video connection failure retries the display after 0.5, 1 and 2 seconds, with at most three recoveries per minute. A sustained media-timeline deficit can also trigger display-only catchup, with at least ten seconds between catchup attempts and the same shared cap. These recoveries preserve the native session and audio. If the budget is exhausted or the browser cannot decode the stream, the page asks for **Reconnect** instead of retrying indefinitely.

## Audio and compatibility

- **Phone / Bluetooth is the default.** A firmware-specific, session-scoped adapter keeps CarPlay from claiming the phone’s audio output. It does not pair Bluetooth devices or send steering-wheel commands; those use the existing phone/car Bluetooth connection.
- The user reported successful actual Tesla Bluetooth audio after the beta 4 changes. This is separate from the measured iPhone-speaker trials and does not establish steering-wheel-control or navigation-prompt compatibility.
- Optional **Browser audio** receives music and navigation output through authenticated native audio streams. PCM is supported; AAC-LC decoding is included and tested with independent synthetic vectors on the device. HTTPS3 uses the browser’s secure WebCodecs API to draw native H.264 frames onto a canvas. It does not modify Tesla firmware, read the gear state or change vehicle settings. Desktop checks do not establish in-vehicle presentation or safe operation. Perform setup and media tests while parked.

See `TEST-RESULTS.md` for the actual negotiated formats and device trials.
- **No microphone capture or voice-call/Siri input in this beta.** iOS 16 requires duplex format declarations to construct its audio table. A requested input stream sends authenticated digital silence and reports `mutedInput`; it does not record the phone or car microphone. Use a separate supported route for calls.
- CarPlay-compatible app interfaces come from iOS. **CarBridge is required for the arbitrary/full-app interfaces tested on the development phone.** This package neither bundles nor replaces CarBridge. Apps without native CarPlay support are not promised to work on a phone without it. Other preexisting tweaks can affect compatibility.
- Experimental accessory authentication was accepted on the supported device. This is not MFi certification or a guarantee on other iOS versions.
- HTTPS3 requires secure WebCodecs support and browser permission to contact the local iPhone. It does not silently fall back to JPEG or MediaSource on the hosted page. The local HTTP page retains capability-based fallback paths; the experimental native JPEG decoder failed on the supported iPhone and is not a validated alternative to the hosted renderer.
- HTTPS3 Tesla responsiveness, Personal Hotspot interruption/recovery, navigation prompts mixed with music, steering-wheel controls, long-duration temperature/battery behavior and other tester environments still require vehicle testing. Historical home-Wi-Fi operation and Bluetooth reports do not establish these results.

## Access, diagnostics and removal

Use a trusted Personal Hotspot: connected local-network devices can open and control CarDash without a pairing code. The local browser receives an automatic service token. The hosted page obtains a separate, memory-only bearer token after Connect; the service accepts cross-origin control only from the exact approved HTTPS origin with that token. Stale native-session controls are rejected. This is trusted-hotspot access, not phone-owner authentication; there is no setup code to enter. There is no analytics or automatic report upload.

The service records bounded browser viewport/playback counters, pause/visibility state, decoder errors, request timings, input/recovery counts and a random non-credential per-tab identifier roughly every 12 seconds during a session. Native encoder demand, measured encoded data rate, queue occupancy and applied device-output policy are also recorded. Media-timeline deficit is diagnostic; it is not a measurement of physical display latency. It does not read the car’s gear state. The service rotates its receiver event log and stores its own receiver identity under `/var/jb/var/lib/cardash-v3`. It does not record video or audio. **Export diagnostic report** combines bounded tails of installation, service and native-session logs, counters and errors. Installation and startup log files themselves are retained. Private keys and browser credentials are excluded; review the report before sharing.

Removing V3 stops its service, unloads its adapter by restarting the media service, and retains its identity/reports. It does not delete original CarDash or V2 preferences. Earlier diagnostics/V2 test packages are removed separately on the development phone after validation; this installer does not silently uninstall other packages on testers' phones.

If a session fails, export diagnostics and try Stop → Start. The status distinguishes native startup, waiting for video, and browser playback; exported status and startup errors also identify whether the USB-free transport adapter loaded. Diagnostics include service startup stages and native input responses to distinguish a launch failure from an inactive interface. Stop any other real CarPlay connection first: V3 will not replace an existing native session. Record package version, phone/build, car/browser version, app and lock state. Initial identity preparation and the first unlock after a respring/reboot still require phone access.
